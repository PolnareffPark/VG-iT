# Implementation Notes

## Scope and fidelity

This document records implementation behavior observed in the VG-iT v1.0.0 reproducibility package. It makes exact reruns and interpretation of generated diagnostics explicit. The canonical results distributed with this package were not recomputed while preparing these notes, and the archived model, training, and evaluation logic was not changed.

## Fixed-window grouping and padding

In the fixed-window path, the attention-token axis is padded with zero-valued query, key, and value tokens until its length is divisible by the configured number of groups (`code/layers/Hierarchical_Attention.py`). This path does not apply a padding mask to local attention, and padded positions participate in subsequent mean, maximum, or statistical group pooling. Padded positions are removed from the final token output after local-global integration.

Consequently, when the embedded token count is not divisible by the number of groups, padded tokens affect local-attention normalization and group representatives. Exact reruns of the archived implementation should retain this behavior. Introducing a local-attention padding mask is a model change and may change numerical results.

## FiLM initialization

The learned FiLM projection weights and biases are initialized to zero in `code/layers/Hierarchical_Attention.py`. The implemented modulation is:

```text
gamma = 1 + film_gamma(global_context)
beta = global_context + film_beta(global_context)
output = gamma * local_output + dropout(beta)
```

At initialization, the implemented expression is therefore `local_output + dropout(global_context)`, rather than the local-only identity mapping. "Zero-initialized" refers to the learned gamma and beta projection residuals.

## Forecast-loss command-line option

`code/run.py` declares `--loss` as `args.loss`, whereas the main experiment selects a criterion from `args.forecast_loss` and defaults to MSE when that attribute is absent. In v1.0.0, passing `--loss` does not change the main experiment criterion. The supplied reproduction scripts do not pass this option and use the resulting MSE criterion.

## Standard test-loop throughput field

The standard test data loader uses batch size 1. The non-efficiency test summary computes `infer_speed_items_s` using the configured training `args.batch_size`. Accordingly, that standard-summary field should not be interpreted as measured test items per second when `args.batch_size` is greater than 1. The reported `infer_latency_s` remains elapsed seconds per test iteration. Efficiency-profile records produced through `EfficiencyCollector` use separately recorded timing fields.

## Precomputed grouping-plan archive

`code/scripts/precompute_grouping_plans.py` writes permutations to `test_results/probing_classifier/grouping_plans.npz`. The v1.0.0 training and reproduction entry points do not load this NPZ file; grouping plans are computed by the active `run.py` path. The script is a standalone grouping-plan export and inspection utility, not an acceleration cache consumed by the supplied benchmark scripts. Its keys have the form `dataset__method__seed`, and the score-stratified export uses prediction length 96.

## Scaler cache invalidation

The scaler cache key in `code/data_provider/data_loader.py` uses the data path, feature mode, and training-array shape. It does not include file content or modification time. A scaler cache created for an earlier file with the same path and shape can therefore be reused after the file contents change. Remove `.scaler_*.pkl` files after replacing a dataset in place.

## Legacy partial-training path

The optional `partial_train` experiment follows an older execution path. It loads checkpoints without the explicit `weights_only=True` argument used by the main experiment and uses the legacy CUDA autocast context without dispatching on `--amp_dtype`. These details do not affect the supplied main-result reproduction scripts, which use `Exp_Long_Term_Forecast`.

## Efficiency protocol identifier

Efficiency metadata generated by the released runner uses the public protocol identifier `vgit-efficiency-profile-v1`. This public identifier replaces an internal metadata label; the measurement procedure is unchanged.
